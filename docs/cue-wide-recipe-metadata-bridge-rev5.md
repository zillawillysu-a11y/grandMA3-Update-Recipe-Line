# Rev5 reference metadata bridge, grandMA3 2.5.0.3

Revision `5_REFERENCE_METADATA_BRIDGE` is a separate diagnostic candidate. The production plugin, reverse engine, Rev2/3 native proof gates, and Rev4 normalization rules are unchanged. The Rev4 cache now retains each successful raw reference result and exposes a dependency registration method; its finalized `BASELINE_METADATA` result and counters are copied before the bridge runs. The oracle still runs last, with no Cue/Part metadata read or cooked fallback.

The user's Rev4 native result is authoritative: 25 direct references, 25 reads, 71 hits, native read total 4.871 ms (0.195 average, 0.393 maximum); Rev4 normalization 205.458 ms, cache 225.638 ms, reverse 95.910 ms, metadata path 321.553 ms. COMPLETE 0, PARTIAL 15, UNKNOWN 10; zero active refs versus four oracle refs. These exact values/IDs are evidence only, never runtime rules.

The candidate first analyzes raw ordinary Preset UI-channel records. For each numeric UI index, it resolves an actual Attribute handle through the record or GetAttributeByUIChannel, then typed Feature and FeatureGroup handles. Explicit finite numeric step.absolute / step.relative or release flags establish candidate lanes. One effective step per channel is static only if all relevant records in the reference have feature/layer evidence, no conflicting active masks, and no ambiguous motion/dependency data. `mask_active_phaser`, `mask_active_value`, `mask_cooked`, and `dict_flags.blocked`/`blocked_rel` are checked using installed 2.5 system-test semantics. `dict_index` is type/range checked as a record locator and `gridposmatr` must be empty for this supported subset. Nonzero cooked or dynamic masks, blocked flags, nonempty matrices, unknown effect fields, invalid types and opaque dependencies remain PARTIAL. Each structural record pattern is aggregated and logs an example with field types and values; no per-channel dump is printed.

When a direct reference has empty data but contains a native PhaserRecipe, the bridge walks its typed Recipe ¡÷ Step ¡÷ ValueSource tree read-only. It inspects enumerated versus default raw/effective fields, actual Attribute/Feature/FeatureGroup handles, linked Preset and Shape handles, step index, and dependency handles. A linked Preset is registered in the **same per-run DB identity cache** and read at most once even when several ValueSources refer to it; it need not be a direct Recipe value. Recipe and dependency read counts and timings are separate. Cue/Part/Sequence/unregistered targets are rejected before native GetPresetData.

`PHASER_STRUCTURE_PROVEN` only means the native tree exists. `MOTION_PROVEN` requires two distinct effective step values for the same feature/layer, fully resolved linked metadata when present, and no unsafe source. A single Recipe class, Shape presence, or raw zero does not establish motion. Explicitly enumerated raw numeric values require numeric effective value or a matching complete linked Preset lane. Raw zero without matching linked-layer proof stays ambiguous; mixed/unknown layers remain unsafe. `STATIC_PROVEN` for the ordinary subset requires every relevant effective channel to be one-step static. The bridge never infers from Preset names or numbers.

The bridged metadata has `features`, `layers`, per-lane motion, `completeness`, `evidence`, and source `ORDINARY_GETPRESETDATA`, `PHASER_NATIVE_BRIDGE`, or `MIXED`. Only COMPLETE rows enter the unchanged recipeReverseResolve engine; PARTIAL/UNKNOWN are safety barriers. Group overlap, partial overwrite, static termination, re-source, and sf_index member identity still come from the existing engine. Rejected older moving rows print a bounded first-newer Recipe/member overlap trace. No reference identity is collapsed before member/lane resolution.

Timing separates direct ordinary cache reads, newly read dependency cache work, Phaser tree inspection, bridge ordinary normalization, and reverse. `TOTAL_BRIDGED_PATH_MS` includes the already-required shared direct-reference cache build, the bridge build, and bridged reverse; it excludes Rev3 audit and the Rev4 baseline reverse so that the candidate is not charged for a comparison-only pass. Native read total and hit counts include both direct and dependency references. This is diagnostic timing, not native latency acceptance.
