## Previously Impossible Features Worth Retesting

1. **不用完整 cooked channel scan 找到 Cue 候選 Pool sources — NEW POSSIBILITY。** 以 Cue/Part/StandardRecipe/PhaserRecipe 的 GetDependencies 做 read-only graph probe。S4 證明方向與基礎作用，但沒有證明 inherited active references；失敗時仍需區分「graph沒這項」與「不存在effects」。不要只讀 Sequence 的所有dependencies就標成Current Cue。
2. **Generator/Random alias 無須比較 command-address text — CLEAR UPGRADE（區域性）。** 對 Recipe.Generator 與 PoolObject:Ptr(ObjectIndex) 的已resolve handles 用 CompareHandle；記錄HandleToInt/HandleToStr/native地址作診斷。只驗證identity，不偽稱跨Show stable UUID。
3. **Recall View 與視窗變化驅動區域性 rediscovery — WORTH TESTING。** HookDelete、generic UI dirty hook與screen config target可能減少7-display traversal；必須測試valid-but-hidden、同view重複Recall、新增Pool、替換display、關閉視窗，證明沒有漏通知。不能僅用HookDelete。
4. **無需每refresh掃描historical Recipes，仍立即處理Recipe deletion/NEW CONTENT — WORTH TESTING。** 使用 mutation dirty flags；驗證新增/刪除/Enabled/Values/Generator/Group membership/MAtricks/Undo/import及引用物件變更。hook callback只置flag，不在callback跑native scans或nested coroutines。

## Which workarounds may be removed

**本輪沒有任何 workaround 可以僅憑研究就安全刪除。** 最明確的區域性替代是 CompareHandle，可在Generator alias實測成功後縮減sameReference的text equality路徑；ToAddr仍需用於Cmd與labels，不應全面刪除。

其他為條件式：2.5-only支援政策與實測透過後才能移除GetProgPhaser one-arg fallback；mutation hooks覆蓋全部變更後才能替換每tick scanTracking與「external edits要restart」快取限制；UI notifications覆蓋hide/rebuild後才能縮減rediscovery polling。GetPresetDataFast尚不能替換current keyed-table reader。Recipe string resolver、Enabled gate、StandardRecipe gate、visibility gate、bounded工作、Undo/read-back/rollback應繼續保留。
